# AOS-042 — Guest training sandbox

## Contract

Public route: `/demo`, no account required. This is a **separate, illustrative teaching experience**, not an unauthenticated version of the persistent game. It must never request Supabase Auth, database RPCs, editorial content or multiplayer endpoints.

- Four authored fictitious Arcadia dossiers and twelve policy alternatives.
- Option-first review; no economic or political effect until explicit confirmation.
- Deterministic ordered effects on local treasury, approval, institutional trust, household support and business support. These fixture values are **not** generated by the production PostgreSQL simulation and must not be represented as predictions.
- Exactly one decision per dossier; immutable in-session history with both before/after metrics; proceed to any pending dossier.
- Only IDs and schema version in browser `localStorage` under `aos:guest-training:v1`. Derived metrics are always recalculated from a static allowlist. Corrupt, old, duplicate or modified option references are rejected and start a fresh demo. No email, personal data, credentials, tokens or actual government IDs are stored by the demo.
- Explicit two-step reset removes only the guest-demo key. If browser storage is disabled, play remains possible for the active view, with honest loss-of-resume messaging.
- Links from guest demo to real login and multiplayer, but **no automatic account merging or promotion** of sandbox choices.

## Acceptance

1. `npm run typecheck`, `npm test`, `npm run build` and `npm run test:oracle` pass.
2. `src/demo/demoEngine.test.ts`: versioned deterministic replay, idempotence prevention, validation, bounded metrics, invalid state and denied storage.
3. `src/DemoApp.test.tsx`: guest landing, review/sign, reload-style remount, second dossier, reset and corruption recovery.
4. `tests/demo-browser.mjs`: actual Chromium on 390px and 1440px, decision/reload/second decision/reset, no Supabase requests, WCAG 2.1 A/AA scan and retained screenshots. Executed by `.github/workflows/quality.yml` on pull requests.
5. Public `/demo` renders without Supabase environment variables or browser authentication.

## Limits and product release

This epic improves anonymous product evaluation and a zero-friction onboarding funnel. It does **not** close any of the original 18 strict MVP acceptance gates: real ten-party Auth, live news sourcing, long-term economic balance, editorial QA and design review remain separate. No SQL migration is required, and no cloud data is modified. No claim of a new globally verified progress percentage is justified until CI succeeds and the original gates are re-evaluated.

## Operational verification

On any staging deployment, open `/demo` without login and use browser network tools to confirm no requests to Supabase. Refresh to verify demo-only progress remains, then reset and ensure the official government is unaffected. Repeat in mobile browser, disabled storage, keyboard-only navigation and a screen reader as final manual acceptance.
